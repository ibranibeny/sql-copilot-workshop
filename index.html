01

Understand the assistant

GitHub Copilot overview

GitHub Copilot is an AI coding assistant that helps developers understand, write, explain, and improve code. In a database workflow, it is most useful as a collaborator: it proposes queries and explanations while the DBA retains control over permissions, correctness, and deployment.

Ask

Explain unfamiliar systems

Ask natural-language questions about code, schema, and database behavior without leaving the editor.

Build

Draft and refine code

Generate T-SQL, document intent, refactor a query, and review the proposed change as a diff.

Agent

Work through goals

Agent mode can select tools and iterate through a task, but it never receives permissions beyond the connected identity.

Evidence rule: Copilot output is a hypothesis, not proof. Query Store, execution plans, bounded MCP diagnostics, and result-equivalence tests decide whether a change is safe.
02

Work where the database lives

GitHub Copilot in SSMS

Microsoft documents GitHub Copilot as an AI assistant in SSMS 22 or later. Install the AI Assistance workload, connect a query editor to the database, open the Copilot badge, and sign in with a GitHub account that has Copilot access.

  • Chat and inline chatAsk general SQL questions or questions grounded in the active editor and database connection.
  • Code completions and Next Edit SuggestionsReceive T-SQL ghost text and likely next edits based on the connected schema and current file.
  • Slash commandsUse focused assistance such as /explain, /fix, /optimize, and /doc.
  • Database instructionsUse CONSTITUTION.md to provide durable database rules and an optional execution identity.
  • Agent mode and skillsAgent mode works through a goal; skills provide reusable task-specific instructions.
  • MCP serversAgent mode can discover and call MCP tools. Tools are disabled until explicitly enabled and remain permission-constrained.
Security boundary: Ask mode’s read-only classification is not a security boundary. SQL Server permissions remain authoritative; use least-privilege SELECT and EXECUTE grants.
03

The business problem

AI schema exploration and SQL query optimization

Adventure Works has an unfamiliar schema and a month-end report that has become expensive as sales history grows. The DBA must understand the database, identify the query shape, and optimize it without changing a single result row.

ExploreAsk Copilot how many tables exist, what Sales.Store represents, and how key entities relate.
InspectRead lab.FactSales and lab.usp_MonthEndSalesBaseline; attach the query or plan as context.
MeasureUse Query Store and six bounded SQL MCP diagnostics for runtime, waits, plans, and memory-grant evidence.
ProveBuild one candidate beside the baseline, verify result equivalence, run frozen A/B trials, and decide.
Schema exploration

From catalog to business meaning

Copilot can summarize objects and relationships, but the active login controls what it can inspect. In the workshop, schema exploration is connected to AdventureWorks2022 and reviewed by the DBA.

Query optimization

From symptom to verified change

Query Store narrows attention to top resource consumers and wait categories. MCP returns described, bounded evidence; Copilot turns that evidence into ranked hypotheses and candidate changes.

Build the disposable lab

Deploy the workshop step by step

Run these steps from PowerShell 7.4 or later. Deployment is billable and phrase-gated. Never place secrets in source control, terminal screenshots, or chat.

1

Clone and pin the reviewed commit

Paste the exact 40-character commit SHA that was reviewed; do not treat the repository’s current HEAD as approval.

$repositoryCommit = Read-Host 'Reviewed 40-character commit SHA'
      if ($repositoryCommit -cnotmatch '^[0-9a-f]{40}$') { throw 'Invalid commit SHA.' }
      git clone https://github.com/ibranibeny/mcp-sql-query-store-workshop.git
      Set-Location ./mcp-sql-query-store-workshop
      git fetch origin $repositoryCommit
      git checkout --detach $repositoryCommit
      if ((git rev-parse HEAD).Trim() -cne $repositoryCommit) { throw 'Commit pin failed.' }

DECLARE @WideWork table
(
  SyntheticSalesID bigint NOT NULL,
  TerritoryID int NULL,
  CustomerID int NOT NULL,
  ProductID int NOT NULL,
  OrderQty smallint NOT NULL,
  SalesAmount decimal(19,4) NOT NULL,

INSERT @WideWork
SELECT fs.SyntheticSalesID, fs.TerritoryID, fs.CustomerID,
       fs.ProductID, fs.OrderQty, fs.SalesAmount, fs.WidePayload
FROM lab.FactSales AS fs
WHERE CONVERT(date, fs.OrderDate) >= @StartDate
  AND CONVERT(date, fs.OrderDate) < @EndDateExclusive;

-- The baseline later reads lab.FactSales a second time for price statistics.

The baseline in sql/04-CreateBaselineProcedure.sql wraps OrderDate in CONVERT(date, …), materializes the unused char(400) payload, aggregates late, and reads the fact table again. With 8,000,000 workshop rows and no candidate index, this increases scans and query-workspace memory.
